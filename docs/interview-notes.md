# Interview notes

These notes cover concepts present in the application. Follow the code walkthrough to rehearse a request from browser to database.

| What | Why | Where in code | Likely interview question | Short answer |
| --- | --- | --- | --- | --- |
| JDK and JVM | Compile and run Java 21 | `backend/pom.xml`, `OpsDeskApplication.java` | How do JDK, JRE and JVM relate? | The JDK supplies compiler and development tools plus a runtime. The JVM executes bytecode. JRE describes the runtime libraries and JVM; modern JDK distributions include that runtime. |
| Spring Boot autoconfiguration | Start a small app without hand-configuring Tomcat and a datasource | `@SpringBootApplication`, `application.yml` | What does Boot configure? | Based on dependencies and properties it creates the web server, datasource, JPA infrastructure and health endpoint. |
| Spring bean | Let the application context manage dependencies | `OpsDeskApplication`, test constructor | What is a bean? | An object managed by Spring; configuration and autoconfiguration register beans. |
| Constructor injection | Dependencies are explicit and can be final | `BackendFoundationTest` | Why constructor injection? | The required dependencies are visible when constructing an object; no field injection hides them. Here Spring injects the HTTP test client and JDBC helper. |
| Maven parent/dependency management | Keep compatible library versions together | `backend/pom.xml` | Why are starter versions omitted? | The pinned Boot parent supplies tested dependency versions. It does not mean we use an unpinned latest version. |
| JPA and Hibernate infrastructure | Prepare relational persistence | JPA dependency and `application.yml` | Are JPA and Hibernate the same? | JPA is the API/specification; Hibernate implements it. User, Incident, Comment and IncidentActivity are mapped entities. |
| Schema validation and Flyway | Avoid silently changing tables at startup | `ddl-auto: validate`, Flyway dependencies | Who changes the schema? | Flyway applies versioned SQL migrations; Hibernate validates the resulting schema against entity mappings. |
| Open Session in View disabled | Keep lazy database reads inside deliberate service boundaries | `spring.jpa.open-in-view: false` | Why disable it? | Controllers should return DTOs rather than depend on database access during response serialization. Services map entities to response DTOs within their database access boundaries. |
| Integration test | Exercise real server and real PostgreSQL together | `BackendFoundationTest` | How does this differ from a unit test? | It starts the application on a random port, sends HTTP, and queries a separate PostgreSQL database. |
| Actuator health | Give operators a basic availability check | `application.yml`, foundation test | Why hide health details? | Public callers need status, not internal configuration. Only health is exposed. |
| BCrypt | Store a slow, salted password hash | `SecurityConfig.passwordEncoder`, `AuthService.register` | Why not encrypt passwords? | Authentication only needs comparison, so one-way adaptive hashing is safer than reversible encryption. BCrypt embeds its salt and cost in the hash. |
| JWT | Carry authenticated identity between stateless requests | `JwtService`, `SecurityConfig` | What is inside the token? | Email subject, issuer, timestamps and one role claim. HS256 signs it; it is encoded, not encrypted, so secrets do not belong in claims. |
| 401 vs 403 | Give correct authentication and authorization outcomes | `SecurityConfig`, `AuthIntegrationTest` | What is the difference? | 401 means no acceptable authentication was supplied. 403 means identity is known but lacks permission. |
| Backend authorization | Make access rules authoritative | `UserController.listUsers` | Why is a frontend role check insufficient? | A caller can bypass the UI and invoke HTTP directly. Spring checks the signed role at the protected method. |
| DTO vs entity | Prevent persistence internals and hashes from leaking | `UserResponse`, `User` | Why not return the User entity? | The entity contains `passwordHash` and database concerns. The response explicitly contains only safe API fields. |
| Bean Validation | Reject malformed input before service logic | `RegisterRequest`, `LoginRequest` | Where is validation triggered? | `@Valid` on controller request bodies applies constraints and the global handler returns readable field errors. |
| Transaction | Make registration's database work one unit | `AuthService.register` | Why put `@Transactional` here? | The uniqueness check and insert form one operation; the database constraint remains the final race-safe check. Read-only login avoids accidental writes. |
| Spring Security authentication | Compare credentials and establish identity | `SecurityConfig.userDetailsService`, `AuthService.login` | How does login work? | The authentication manager loads by email and uses BCrypt to compare the submitted password with the stored hash. |
| Role enum | Restrict roles in Java and SQL | `Role`, `V1__create_users.sql` | Why use an enum? | The permitted set is explicit, type-safe and mirrored by a database check constraint. |
| Priority matrix | Keep a critical rule deterministic | `PriorityCalculator` | Why not ask ML for priority? | Impact and urgency map through an auditable nine-case rule that is fully unit tested. |
| State machine | Prevent invalid lifecycle changes | `IncidentTransitionValidator` | Why validate transitions explicitly? | The allowed next states are visible in one small map; CLOSED → IN_PROGRESS becomes a clear 400. |
| Many-to-one | Link incidents to reporter and optional assignee | `Incident` | Why two User relationships? | Both columns are foreign keys to users but represent different roles; lazy loading avoids automatic graph loading. |
| Optimistic locking | Detect competing assignment updates | `Incident.version`, migration V4 | What happens on a race? | Hibernate includes the version in UPDATE; a stale writer affects no row and becomes 409. |
| Scheduled work | Detect SLA breaches without user requests | `SlaBreachChecker` | How is duplicate activity prevented? | The query selects only false flags, and the flag plus activity commit in one transaction. |
| TF-IDF | Convert ticket words to weighted numeric features | `train.py` | What does it capture? | Terms frequent in one ticket but less common across tickets receive more weight; it does not understand meaning like a language model. |
| Logistic regression | Produce category probabilities for a small text classifier | `train.py` | Is confidence hardcoded? | No. `/predict` selects the largest value returned by `predict_proba`. |
| Graceful degradation | Preserve the core ticket workflow during ML failure | `IncidentCreationService`, `AiClassificationClient` | Why call before the transaction? | Network waiting should not hold database resources. Failure returns no suggestion and Java still saves the incident. |
| React client state | Keep the small UI understandable | `lib/auth.ts`, `AppShell.tsx` | Why `useSyncExternalStore`? | Browser storage is external to React. The hook supplies a stable snapshot and notifies mounted components when login/logout changes it. |
| Frontend authorization | Improve usability while Java stays authoritative | `AppShell`, incident detail page | Can hiding a button secure an API? | No. Users can call HTTP directly, so Spring method and service checks enforce roles and ownership. |
| CORS | Allow the configured browser origin | `SecurityConfig.corsConfigurationSource` | Is CORS authentication? | No. It is a browser cross-origin rule. JWT authentication and authorization still protect the API. |
| Token storage | Keep the MVP deployment simple | `lib/auth.ts` | What is the trade-off? | `localStorage` is simple but exposed to successful XSS. Production can move refresh state to Secure HttpOnly cookies and add strict CSP. |
| OpenAPI and Swagger | Make the REST contract discoverable and manually testable | `OpenApiConfig`, `/v3/api-docs` | How do you test protected endpoints in Swagger? | Login first, copy the returned token into Authorize, and Swagger sends it through the configured HTTP Bearer scheme. |
| Global exception handling | Give clients stable, readable errors without leaking stack traces | `GlobalExceptionHandler`, `ApiError` | Why handle specific exceptions before `Exception`? | Specific handlers preserve correct 400/403/404 outcomes; the final catch-all logs unexpected failures and returns a safe generic 500. |
